# ARIA 통합 화면 요청 — v1

2026-09-12 · 촬영 실행 요청 전 검토용. 이 문서 작성 자체는 원 프로젝트 변경·서버 기동·외부 API 호출을 승인하지 않는다. 프로젝트별 담당 작업이 기존 동작을 확인하고 가능한 화면만 인계한다. 최종 사례 선정 후 필수 요청을 좁힌다.

## 모든 캡처의 공통 조건

- 원 저장소 revision, 촬영 시각, viewport, 화면 경로, 재현 단계, 실행 환경, 합성 데이터 조건을 동반한다.
- 개발/테스트 화면이면 그렇게 표시한다. 실제 서비스 UI와 테스트 콘솔·설명 도식을 섞지 않는다.
- 본인 소유 테스트 계정, 격리 DB/Redis만 사용한다. 실제 결제·실제 키·유료 AI·운영 데이터·공개 인증 우회 금지.
- 이름·연락처·계좌·토큰·쿠키·인증 요청 식별자·회의 참가자 얼굴/음성 노출 금지. 촬영은 합성 데이터부터 구성하고 불가피한 식별자는 비식별화 승인 후 재사용한다.
- 웹은 1440×900 정도, 모바일은 390×844 정도의 CSS viewport와 충분한 해상도 권장. 기기 합성 없이 원본 화면으로 전달한다. 상태가 읽혀야 하며 숫자를 보기 좋게 변경하지 않는다.
- 각 파일에 근거 claim/source ID, 공개 재사용 가능 여부, 캡처가 입증하지 않는 범위를 함께 적는다. 긴 비디오보다 핵심 상태 2~3장과 짧은 전환 영상이 우선이다.

| CAP-01 대표 후보 | 승인 응답 유실 후 UNKNOWN/계약 대기 → 조회·대사 → PAID/ACTIVE | 합성 주문 1건, fake gateway 장애 주입, 운영자 테스트 권한. 실제 PG 장애를 연출하지 않음 | 재승인을 피하고 대사로 복구한 판단 설명 |
| CAP-02 대표 후보 | 미납 배치 결과, 유예·실효 경계, 중단 후 동일 실행 재개 | 합성 계약, 테스트 정책·시계, 운영자 권한. 기존 delinquency desktop/mobile 파일 재사용 가능 여부 먼저 확인 | 시간 경계와 재시작 가능성 설명 |

| CAP-04 선택 | 허용 약관 ID·증빙 부족 → DRAFT → 담당자 검토 이력 | 비의료 합성 fixture, 기존 승인된 테스트 응답만. 실제 모델 응답/테스트 응답 구분, 새 유료 호출 금지 | AI 근거와 최종 판단 책임 분리 |

현재 있는 화면: 원 저장소 `docs/evidence/delinquency-desktop.png`, `delinquency-mobile.png`. 아직 포트폴리오용 공개 캡처로 승인한 것은 아니다. 결제/AI UI가 없다면 새 관리자 화면을 만들어 찍지 말고 테스트 결과와 상태 전이 자료를 인계한다.

| --- | --- | --- | --- |
| RND-01 대표 기술 근거 | 늦은 poll·이전 방 정리의 전후 결과, revision·시나리오별 위반 횟수 | 격리 Redis·합성 사용자. 기존 원본 결과가 우선, 운영 성과처럼 표시하지 않음 | Lua 원자 처리와 조건부 정리 설명 |
| RND-02 선택 기술 근거 | PENDING 유지, VERIFIED 본인 1회 소비, 타인 거절 | 승인된 테스트 profile/전용 Redis, 인증 우회 공개 금지 | 인증 결과의 소유권·일회성 |
| RND-03 선택 기술 근거 | 현재 방 비회원 API 403, 탈퇴 후 접근 거절 | 합성 토큰, 로그 토큰 원문 가림, OpenVidu mock이면 명시 | 로그인 여부와 방 권한의 차이 |
| RND-04 서비스 화면 조건부 | 실제 인증 입장·마스킹 초기/시간 경과 상태 | 원 프로젝트 담당자가 실행 가능 확인 후. 카메라/합성 영상 소스와 참가 동의 필요. 제3자 실제 얼굴 금지 | 서비스가 하는 일을 빠르게 이해 |

지금은 신뢰 가능한 실제 서비스 캡처가 없다. 포트폴리오에서는 CSS 기기 테두리와 명시적 캡처 대기 문구를 사용한다. RND-01~03을 서비스 UI로 꾸미지 않는다. RND-04의 실행·영상 의존성이 갖춰지기 전에는 인물이나 마스킹 화면을 생성하지 않는다.

## SAN — 패킷 확인 후 구체화

현재 아래 항목은 성과 주장이 아닌 촬영 후보다. claim ID·구현 revision·실제 지원 흐름을 패킷에서 확인한 뒤 선택한다.

| 요청 ID | 확인할 장면 | 조건·목적 |
| --- | --- | --- |
| SAN-01 | 크롬 확장 프로그램에서 자료 저장 → 출처가 남은 저장 결과 | 공개 또는 본인 작성 자료, 권리 확인, 개인 브라우저 정보 제거. 입력 경로와 추적성 설명 |
| SAN-02 | 실제 구현된 검색/아카이브/지식 카드 중 대표 흐름 | 격리 계정·합성 자료. 화면과 선택한 기술 판단이 연결될 때만 채택 |
| SAN-03 | 선택된 기술 문제의 테스트 또는 측정 결과 | revision·표본·실행 조건 동반. 기존 페이지의 p95·120초 수치 자동 재사용 금지 |

## 프로젝트 담당자가 돌려줄 최소 패킷

파일 경로 / 프로젝트·시나리오 ID / revision / 촬영 시각 / viewport / 재현 단계 / 권한·합성 데이터 / 외부 의존성 / claim·source ID / 공개 재사용·비식별화 확인 / 실패·미지원 상태.

서비스 UI가 없거나 안전한 재현이 불가능하면 `캡처 없음`과 이유를 전달한다. 포트폴리오 작업이 원 프로젝트를 임의 수정해 증거 화면을 만들지 않는다.

# 컴포넌트·콘텐츠 계약 v1

이 문서는 구현 명세 초안이다. 실제 컴포넌트나 공개 콘텐츠를 생성하지 않는다.

## 컴포넌트 책임

| 컴포넌트 후보 | 책임 | 금지/실패 대응 |
| --- | --- | --- |
| ProjectStore | 세로 프로젝트 목록과 아래 사례로 이동 | 외부 페이지처럼 보이는 CTA 금지 |
| PersonalStrengths | 다현의 강점 문장 3개와 각각 프로젝트 1~2개의 판단 장면 | 공식 인재상 이미지·슬로건만 나열하지 않음 |
| ProjectCaseStudy | 프로젝트 소개, 역할, 연속된 사례 본문 | 사례 전체를 탭 뒤에 숨기지 않음 |
| CaseSummary | 위험과 판단을 짧은 한국어로 제시 | 슬로건·과장된 성과·강제 대비 문장 금지 |
| EvidenceStage | 실제 캡처와 화면 상태 설명 | 캡처 미접수/오류 시 명시적 빈 상태 |
| DeviceFrame | 실제 캡처 비율을 보존하는 기기 테두리 | 웹/모바일 캡처 혼동, 핵심 영역 crop 금지 |
| DecisionRail | 위험·판단·구현·검증 설명을 문서 순서대로 표시 | 핵심 텍스트를 animation 종료 후에만 표시하지 않음 |
| StateReplay | 동일 사례의 강조 상태만 선택적으로 재생 | 실제 서버 호출·결제·AI 호출 금지 |
| EvidenceDetails | 검증 조건·승인된 코드/테스트 링크 | 로컬 절대 경로·내부 장부·비밀값 노출 금지 |
| RoleConnection | 공식 JD/인재상과 행동 근거의 짧은 연결 | 출처 미인계 또는 행동 근거 약하면 렌더링하지 않음 |

소개·본문은 서버 렌더링과 정적 출력에서 읽을 수 있게 한다. 클라이언트 상태는 화면 강조·재생·선택적 펼침에만 쓴다. 프로젝트 API 연결은 하지 않는다.

## 콘텐츠 계약

### 내부 EvidenceRef — 공개 번들에 넣지 않음

- `id`: 포트폴리오 내부의 고유 참조 ID.
- `project`, `packetPath`, `claimId`, `sourceIds`: 원본 장부의 식별자를 그대로 사용. 새 ID로 원본 검증 상태를 바꾸지 않는다.
- `sourceRevision`, `captureRevision`, `observedAt`: 코드·측정·화면의 시점을 각각 저장한다. 저장소 HEAD를 과거 테스트 revision으로 대체하지 않는다.
- `status`: 원본의 VERIFIED / USER_PROVIDED / INFERENCE / UNVERIFIED.
- `reviewLevel`: 패킷 읽음 / 원본 읽음 / 이번 작업에서 재실행함을 구분.
- `roleScope`: 원 팀 담당과 후속 판단·검증·통합 책임, 저자성 제약.
- `metricConditions`: 환경, 합성/실데이터, 표본·반복·동시성, 제외 범위, 원본 결과 경로.
- `permission`: 공개 재사용·권리 확인·비식별화 상태. 빈 값은 승인으로 처리하지 않는다.
- `publicSourceUrl`: 공개 링크로 사용 가능한지 별도 검토한 HTTPS 주소만 허용. 내부 경로를 자동 변환하지 않는다.

### 공개 ProjectCase

- `id`, `anchor`, `name`, `serviceSummary`, `roleSummary`.
- `scenarios[]`: 각 항목에 `id`, `risk`, `decision`, `implementation`, `verification`, `states[]`.
- `verification`: 숫자만 떼어 쓰지 않으며 `로컬 합성 요청 100회`처럼 결과를 해석하는 데 필요한 조건을 본문에 함께 둔다.
- `states[]`: `id`, `label`, `explanation`, `mediaId?`, `annotation?`. 같은 사례 안에서 유효한 참조만 허용한다.
- `media`: 아래의 구별된 상태 중 하나. `captured`만 DeviceFrame 내부 실제 이미지로 렌더링한다.
- `optionalTradeoff?`: 판단의 이유를 설명할 때만 짧게 사용. 필수 한계·실패 섹션 없음.
- `roleConnection?`: 공식 근거와 개인 행동 연결이 승인됐을 때만 공개 문장 추가.

### 미디어 상태

| kind | 필수 필드 | 표시 |
| --- | --- | --- |
| captured | asset, 실제 너비·높이, alt, caption, 캡처 조건 확인 참조 | 원본 화면. 합성 테스트/sandbox이면 캡션에 표시 |
| diagram | 기술 설명, 연결된 claimId, 상태 순서 | ‘처리 흐름’ 표기로 기기 밖에서 표시 |
| awaiting_capture | 필요한 화면, reason, deviceHint | ‘실제 서비스 화면 캡처 준비 중’ |
| unavailable | reason | 이미지 오류/미확보 안내 + 동일 정보의 텍스트 |

정적 스크린샷으로는 화면상 해당 상태만 입증한다. 동시성·일회 소비·중복 방지 주장은 테스트 근거와 함께 설명한다. 애니메이션은 검증 기록의 설명이며 실행 영상인 것처럼 꾸미지 않는다.

## 인터랙션 계약

- 첫 진입: 대표 상태가 즉시 보이고 사례 핵심 문장은 모두 존재한다.
- 단계 선택: `activeStateId`를 변경하고 대응 캡처·설명 강조를 동기화한다. 실제 캡처가 없는 상태는 이전 화면을 재사용해 성공으로 가장하지 않는다.
- 스크롤: 현재 읽는 단계 표시만 갱신하며 스크롤 방향·위치를 강제로 바꾸지 않는다.
- 다시 보기: 사용자가 누른 경우에만 시작. 선택·스크롤·정지·화면 이탈 시 중단하고 상태를 숨기지 않는다.
- 키보드: 네이티브 버튼/링크, 분명한 포커스, 선택 상태 이름 제공. 화살표 아이콘만으로 동작 설명을 대신하지 않는다.
- 모바일: 기기 화면의 내부 강제 스크롤을 만들지 않는다. 필요 시 ‘화면 크게 보기’를 보조 기능으로 두되 핵심 설명은 바깥에 유지한다.
- 이미지·JS 실패, 모션 축소, 인쇄: 정적인 텍스트·검증 요약·출처 이름으로 의미를 유지한다.

## 공개 문구 원칙

- `화면만 만든 게 아니라`, `FROM ... TO ...`, `Social` 등의 장식 문구를 재도입하지 않는다.
- 기술은 선택 이유와 함께 쓴다. 예: ‘인증 확인과 큐 변경을 Redis Lua에서 한 번에 처리했습니다.’
- ‘운영 장애 0’, ‘정확도 향상’, ‘금융 규제 준수 완료’처럼 자료가 지지하지 않는 확장은 하지 않는다.
- ‘실제로 한 일 / 지원용 해석’ 같은 내부 검증 분류를 공개 섹션 제목으로 만들지 않는다. 역할은 짧고 구체적인 담당 문장으로 표시한다.
- 이번 공고의 Discipline · Creative Thinking · Sense of Purpose를 작게 보조한다. 법인 상시 채용안내의 다른 기준으로 대체하지 않는다. SAN 접수 전 개인 강점 문구는 초안 상태로 관리한다.

### 개인 강점 콘텐츠

각 항목은 `personalSentence`, `supportingMoments[1..2]`, `campaignValue`, `meaningSummary`, `sourceLabel`을 갖는다. supportingMoments는 프로젝트 이름, 구체 판단 한 문장, 사례 앵커, 내부 증거 참조를 가진다. 내부 참조는 공개 번들에서 제거한다. 개인 문장이 주제목이고 공식 영어 이름은 보조 라벨이다. 의미를 모두 충족했다고 주장하거나 프로젝트를 인재상에 강제 1:1 배정하지 않는다.

## 콘텐츠 검증 게이트

구현 전 모든 결과 문장을 EvidenceRef에 연결하고, 공개 객체에는 필요한 문장·승인된 링크·비식별 이미지 메타데이터만 선택적으로 내보낸다. 내부 패킷 전체를 import하거나 `public/`로 복사하지 않는다. 근거 없는 수치, 미승인 링크, 잘못된 state/media ID, captured인데 파일·조건이 없는 항목은 검증 실패로 처리한다.

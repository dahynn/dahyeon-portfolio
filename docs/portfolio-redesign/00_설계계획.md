## 목표와 범위

인사담당자가 페이지를 넘기거나 인터랙션을 조작하지 않아도 각 프로젝트의 문제, 판단, 기술 구현, 검증 결과를 읽을 수 있게 한다. 자세히 볼 때는 실제 화면과 기술 설명이 같은 상태를 가리키게 한다.

이번 단계는 이 폴더의 계획·콘텐츠 계약·증거 접수·촬영 요청 작성뿐이다. 현재 포트폴리오 UI, 프로젝트 저장소, 배포, GitHub Actions, DNS는 수정하지 않는다. 커밋·푸시하지 않는다. 기존 `PORTFOLIO_PLAN.md`는 2026-09-09 초기 계획으로, 이번 재설계의 재개 지점이 아니다.

최신 ARIA 정정 지시를 우선한다. 공개 서사는 **위험 → 판단 → 구현 → 검증**이다. 한계·실패는 필수 공개 섹션이 아니며, 기술 판단을 이해하는 데 도움이 될 때만 짧게 사용한다. 내부에는 검증 범위와 미확인을 유지한다.

## 먼저 유지할 것

- 프로젝트 스토어: 사용자가 선택한 세로 App Store 목록, 실제 프로젝트 아이콘, 한국어 설명, `아래로 이동 ↓` 앵커를 유지한다. 새 상세 페이지로 갈 것처럼 보이는 `보기/열기`는 쓰지 않는다.
- 소개: 최신 지시에 따라 향후 앞부분의 강점 소개를 이번 공고 인재상과 프로젝트 판단 장면에 연결하도록 계획한다. 이번 단계의 실제 UI 수정은 없다. 개발 여정의 반응형 상하 여백과 마지막 한화생명 로고는 보존한다.
- 각 프로젝트의 기존 앵커 `#capsure`, `#roundy`, `#san` 및 `*-detail` 링크를 유지하거나 동일 프로젝트 내 의미 있는 위치로 연결한다.
- 기존 색상과 글꼴을 기반으로 한다. 큰 영문 슬로건, Social 같은 장식용 분류, 기술 스택 배지 나열은 늘리지 않는다.

## 독자가 읽는 순서

1. 프로젝트 이름 + 서비스가 하는 일 한 문장 + 담당 범위 한 줄.
2. 가장 중요한 위험과 그에 대한 판단을 제목·두 문장으로 요약.
3. 실제 화면 또는 설명 도식 옆에 판단·구현·검증 문장을 배치.
4. 첫 사례는 조작 없이 전체 요지가 보이게 한다. 추가 사례도 같은 페이지 아래에서 읽을 수 있다.
5. 코드·테스트 근거를 더 보고 싶은 독자에게 선택적 펼침 영역을 제공한다.

기술 이야기를 클릭 뒤에만 숨기는 탭형 포트폴리오로 만들지 않는다. 시나리오 선택은 해당 사례로 이동하고 화면의 강조 위치를 바꾸는 보조 기능이다.

## 레이아웃과 인터랙션

| 환경 | 구성 | 읽기 보장 |
| --- | --- | --- |
| 넓은 PC | 실제 화면 약 55%, 설명 약 45%의 2열 | 설명 길이에 맞춰 문서 높이가 늘어남 |
| 작은 노트북·낮은 화면 | 2열이 답답하면 일찍 1열 전환, 고정 화면 해제 | 하단을 자르거나 한 화면에 억지로 축소하지 않음 |
| 모바일·확대 보기 | 요약 → 화면 → 상태별 설명의 1열 | 가로 스크롤 없이 문서 전체 읽기 |

- 좌우 여백과 함께 반응형 상하 패딩을 둔다. `height: 100vh`와 `overflow: hidden`으로 본문을 제한하지 않는다. 단위·수치는 실제 콘텐츠로 검증한 후 정한다.
- 노트북 모양은 웹 캡처, 휴대폰 모양은 모바일 캡처에만 사용한다. 기기 테두리보다 글씨·상태 변화가 크게 보여야 한다. 기울이거나 잘라 핵심 정보를 가리지 않는다.
- 상태 변화는 화면 강조와 옆 설명 강조를 동기화한다. 자동 재생·자동 다음 사례 전환은 하지 않는다. 선택적 `과정 다시 보기`로 짧은 단계 강조만 실행한다.
- 모션 축소 설정에서는 정적인 최종 상태와 모든 설명을 제공한다. 재생을 끝내야 텍스트가 나타나는 방식은 금지한다.
- 긴 사례 구간에서는 기존 `PageSnap.tsx`의 강제 wheel 이동과 mandatory snap을 적용하지 않는다. 키보드·트랙패드·터치로 중간 내용을 건너뛰지 않고 읽을 수 있어야 한다.
- Roundy는 명시적으로 허용된 **CSS 기기 테두리 + ‘실제 서비스 화면 캡처 준비 중’** 빈 상태만 계획한다. 인물·미팅 UI·성공 화면을 생성해 채우지 않는다. 증거 도식은 기기 밖에서 ‘처리 흐름’으로 구분한다.

## 기업·인재상 연결 게이트

ARIA가 읽기 가능하다고 전달한 `research/company-analysis/00_아리아-직무신호-인계.md` 및 인재상 행동 기준 문서를 읽었다. 전체 기업 조사는 partial이며, 등록 근거 범위만 사용한다. 개인 프로젝트 패킷과 결합한 후보 연결은 [직무·인재상 연결](04_직무-인재상-연결.md)에 기록했다. SAN 접수 전 최종 순서는 확정하지 않는다.

이번 공고에 적용할 인재상은 최신 사용자 제공 정정에 따라 **Discipline · Creative Thinking · Sense of Purpose**다. 의미 전문은 ARIA가 전달한 사용자 제공 문구를 기준으로 하며, 캠페인 조사 SRC-001/RCL-027이 세 방향을 보조한다. 법인 상시 채용안내의 다른 인재상을 이번 공고 기준으로 사용하지 않는다.

앞부분은 다현의 언어로 쓴 강점 문장 3개와 각각 바로 아래의 프로젝트 1~2개·판단 장면을 묶는다. 공식 영문과 의미·출처는 작게 보조하고 이미지에 공식 문구만 붙이는 구성은 하지 않는다. 연결은 `공고 의미 → 프로젝트에서 내린 판단·행동 → 코드/검증 근거`가 모두 있을 때만 만든다. 세 프로젝트에 인재상 하나씩을 억지로 배분하지 않으며, 중복 연결이 가능하다. 현재 강점 문구는 CapSure·Roundy 근거로 만든 초안이고 SAN 접수 후 최종화한다.

## 실행 단계와 완료 기준

1. 피드백 자료·CapSure·Roundy 접수 내용을 기록한다. 완료.
2. 기업/JD·정확한 인재상 인계 읽음. SAN 패킷 접수는 대기.
3. 주장·역할·측정 조건·실제 화면의 revision을 대조하고 최종 배치안을 확정한다. 대기.
4. 이 계약을 기준으로 UI를 구현한다. 이번 단계에서는 실행하지 않음.
5. 1440×900, 1280×720, 1024×768, 768×1024, 390×844, 320×740과 데스크톱 200% 확대에서 검증한다.
6. 모든 본문·앵커·상태 선택을 키보드로 읽고 조작할 수 있는지, 모션 축소·이미지 로드 실패·인쇄에서도 핵심 내용이 남는지 확인한다.

검증 통과 조건: 본문 잘림·가로 넘침 없음, 스크롤 강제 건너뛰기 없음, 화면/설명 상태 일치, 미확인 캡처를 실제 UI로 제시하지 않음, 근거 없는 수치·역할·기업 연결 없음. 구현 단계에서 빌드와 배포용 정적 출력 검증을 하되 배포는 별도 승인이다.

CapSure는 보험 업무와 직접 맞닿은 상태·복구 사례로 시작한다. Roundy는 동시성·인증/인가를 깊게 설명하고, SAN은 조회 데이터 규모와 AI 입력·사용자 검토로 범위를 넓힌다. 가치 이름은 사례 제목에 붙이지 않으며 중복 연결을 허용한다. 회사 내부 구조·배점의 재현이 아니라 partial 조사 인계에 근거한 설계 해석이다.

## 앞부분 개인 강점 최종 초안

1. 오류가 나도 복구 결과까지 확인합니다. — CapSure 중단/재개, Roundy 경쟁 검증. Discipline 보조.
2. 반복되는 문제는 처리 방식부터 다시 설계합니다. — Roundy Lua 원자 처리, SAN 서버 검색·결과 집합 대조. Creative Thinking 보조.
3. 고객이 믿을 수 있는 결과를 기준으로 설계합니다. — CapSure 결제 미확정·사람 검토, SAN 입력 근거·검토 상태. Sense of Purpose 보조.

SAN 개인 단독 기여는 미확인이다. SAN 구현·결과는 프로젝트의 설계 사례로 소개하며 팀 리드/독자 구현·운영 성과를 새로 확정하지 않는다. 후속 AI 협업과 기존 팀 담당을 짧은 역할 맥락으로 구분한다. 개별 역할 확인 질문은 내부 후속 목록에 남긴다.

## 구현·캡처 결정

세 프로젝트 모두 연속 본문과 상태 선택을 제공한다. 선택은 처리 흐름과 해당 설명의 강조를 연결하고 본문을 숨기지 않는다. 자동 스크롤 넘김은 제거해 긴 내용이 자연스럽게 읽히게 한다. 기기 내부에는 실제 캡처 또는 명시적 캡처 대기 상태만 놓는다. 처리 흐름과 측정 그래프는 서비스 UI와 구분한 설명 자료다.

촬영 요청의 최종 우선순위: CapSure UNKNOWN→대사 화면, Roundy 입장/시간별 마스킹 실제 화면, SAN 서버 검색과 입력 근거/재시도 화면. 각 상태가 UI에 없으면 새 UI를 만들어 촬영하지 않고 없음으로 인계. 상세 조건은 `03_화면요청-인계.md`.
